# ADR-006 — One durable cloud workflow authority

**Status:** Accepted default — evaluate at foundation gate
**Date:** 2026-10-08
**Owner:** founding technical/product lead

## Context
The product must combine a fast native collaboration experience with inspectable, bounded local/cloud execution. This decision narrows implementation ambiguity while preserving the user's fixed requirements. Read the linked domain/security specifications before treating a mechanism as complete.

## Decision
Use Temporal as the initial shared-run durability backend. Workflow code stays within the SDK deterministic subset. Effect application code executes inside Activities, which normalize typed failures, heartbeat bounded work, and reconcile uncertainty. An Effect-native durable engine can replace this choice only after the same failure/replay/versioning gate and a recorded ADR.

## Consequences and alternatives
Do not run two competing durable authorities for one workload. Ordinary Effect fibers do not constitute a distributed journal. Activities can retry and external actions can have uncertain results; persistence alone does not provide exactly-once effects. Migration of active workflow histories is a separate problem from changing an interface.

## Validation and revisit trigger
Gate: crash/restart, duplicate delivery, approval wait across deployment, history replay/version upgrade, database interruptions, cancellation, and unknown external outcomes. Record operator recovery procedures and retention needs. Re-evaluate once with evidence, not repeatedly during feature tickets.
