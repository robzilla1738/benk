# ADR-001 — Native GPUI desktop

**Status:** Accepted — user-fixed stack
**Date:** 2026-10-08
**Owner:** founding technical/product lead

## Context
The product must combine a fast native collaboration experience with inspectable, bounded local/cloud execution. This decision narrows implementation ambiguity while preserving the user's fixed requirements. Read the linked domain/security specifications before treating a mechanism as complete.

## Decision
The primary application is a Rust/GPUI native desktop client. Browser participation is complementary and does not redefine the desktop as a web shell. The first supported platform is macOS Apple Silicon as a planning default; Windows/Linux input, rendering, accessibility, packaging, and media risks must be investigated early. The owner may change platform order, not the requested framework without explicit authorization.

## Consequences and alternatives
Native rendering alone does not guarantee speed. The team owns composer behavior, IME, accessibility semantics, media integration, platform SDK setup, release signing, and update recovery. Pin one supported GPUI API surface and record exact compiler/SDK versions. Published crates and upstream main cannot be mixed casually.

## Validation and revisit trigger
Gate: compile and run the native shell, execute representative composer/IME/accessibility scenarios, and record whole-process-tree performance on declared hardware. An uncompiled scaffold is not evidence. Revisit platform order when tests or pilot customers justify it; do not substitute Electron or Tauri simply because a local build dependency is missing.
