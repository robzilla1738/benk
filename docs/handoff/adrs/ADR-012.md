# ADR-012 — Inspectable context and publication authorization

**Status:** Accepted — information-flow model
**Date:** 2026-10-08
**Owner:** founding technical/product lead

## Context
The product must combine a fast native collaboration experience with inspectable, bounded local/cloud execution. This decision narrows implementation ambiguity while preserving the user's fixed requirements. Read the linked domain/security specifications before treating a mechanism as complete.

## Decision
Task context is a versioned, inspectable manifest of approved sources, instructions, decisions, and unresolved questions. Source read permission, permission to send content to a model/provider, and permission to publish derived output to an audience are distinct checks. Personal exploration does not automatically become team memory.

## Consequences and alternatives
Search and retrieval are permission-filtered before material reaches an agent. Derived summaries carry provenance and invalidation behavior. Logs, embeddings, caches, and exports participate in retention/deletion policy. Do not claim end-to-end encryption while a server reads plaintext for ordinary processing without a precise exception model.

## Validation and revisit trigger
Gate: private-source/public-channel leakage tests, provider-use policy, source revocation and derived-context invalidation, injection attempts in retrieved documents, and safe logging. Memory promotion needs an accountable owner. A provider-neutral API does not prove every provider satisfies the same privacy requirements.
