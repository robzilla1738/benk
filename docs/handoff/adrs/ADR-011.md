# ADR-011 — Browser reviewer before full web parity

**Status:** Accepted — adoption baseline
**Date:** 2026-10-08
**Owner:** founding technical/product lead

## Context
The product must combine a fast native collaboration experience with inspectable, bounded local/cloud execution. This decision narrows implementation ambiguity while preserving the user's fixed requirements. Read the linked domain/security specifications before treating a mechanism as complete.

## Decision
Desktop is the primary authoring/execution application, but a focused browser client supports authenticated review, comment, approval, and lightweight messaging early. Mobile participation is needed before a broad communication replacement claim. Shared protocols, semantics, tokens, and behavioral tests matter more than forced shared rendering code.

## Consequences and alternatives
Review links preserve authorization and expiration; they do not bypass private resource access. Browser previews are isolated from the trusted review controls. Native developer affordances remain optional so product/design/support participants do not face an IDE-shaped onboarding requirement.

## Validation and revisit trigger
Gate: a second human can review an exact artifact version from a link without installing the native client, while a unauthorized/revoked viewer cannot read it. Accessibility and stale-review behavior must match desktop semantics. Expand web/mobile editing depth only when adoption and parity blockers justify it.
