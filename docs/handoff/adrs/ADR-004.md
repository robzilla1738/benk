# ADR-004 — Privileged broker separated from orchestration

**Status:** Accepted — trust boundary
**Date:** 2026-10-08
**Owner:** founding technical/product lead

## Context
The product must combine a fast native collaboration experience with inspectable, bounded local/cloud execution. This decision narrows implementation ambiguity while preserving the user's fixed requirements. Read the linked domain/security specifications before treating a mechanism as complete.

## Decision
A narrow Rust execution broker validates grants and dispatches approved tools under explicit isolation profiles. Neither GPUI nor the Effect engine gets an unrestricted convenience API for shell execution. An engine proposes operations; current policy and the broker constrain what executes. Credentials are referenced by scoped handles and materialized only at the necessary boundary.

## Consequences and alternatives
Separate processes are fault boundaries, not automatically security sandboxes. Local filesystem/network/process restrictions and hosted isolation require implementation, adversarial testing, and operational configuration. Generated previews cannot inherit application credentials or privileged IPC. Real execution remains disabled until gates pass.

## Validation and revisit trigger
Gate: deny tests for path traversal, symlink escapes, inherited environment secrets, arbitrary network destinations, stale grants, unauthorized child processes, and cross-tenant artifacts. Demonstrate stop/cleanup behavior. Failure of a required isolation mechanism fails closed; do not silently downgrade to unrestricted execution.
