# ADR-003 — Local cache versus shared authority

**Status:** Accepted — architecture baseline
**Date:** 2026-10-08
**Owner:** founding technical/product lead

## Context
The product must combine a fast native collaboration experience with inspectable, bounded local/cloud execution. This decision narrows implementation ambiguity while preserving the user's fixed requirements. Read the linked domain/security specifications before treating a mechanism as complete.

## Decision
Rust owns the native SQLite collaboration cache, drafts, and local outbox. PostgreSQL is authoritative for shared records. The local engine owns a separate execution journal. Account/workspace scoping is mandatory. Reading cached content and composing drafts can work offline; shared approvals and consequential shared mutations need current authority.

## Consequences and alternatives
Local-first is a product behavior, not permission to make every record authoritative on every device. Pending messages must be visibly distinguished from server-accepted messages. Cache eviction, revocation, logout, deletion, and search-index purge are explicit lifecycle operations. Do not share application-table write ownership across Rust and TypeScript processes.

## Validation and revisit trigger
Gate: restart/migration tests, atomic row-and-cursor apply, multi-account isolation, duplicate delivery, edit conflicts, and revocation/deletion search purge. Document the honest limit that an unreachable device cannot immediately receive a deletion instruction. Changes to offline authority require security review.
