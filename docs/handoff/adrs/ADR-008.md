# ADR-008 — Durable events and scoped resumable sync

**Status:** Accepted — initial consistency design
**Date:** 2026-10-08
**Owner:** founding technical/product lead

## Context
The product must combine a fast native collaboration experience with inspectable, bounded local/cloud execution. This decision narrows implementation ambiguity while preserving the user's fixed requirements. Read the linked domain/security specifications before treating a mechanism as complete.

## Decision
Publish shared mutations through a transactionally written outbox. Start with a workspace counter locked in the mutation transaction to avoid sequences escaping commit order. Deliver authorization-filtered streams with their own defined cursor semantics; do not infer gaps or contiguity from invisible global events. Native apply updates data and cursor atomically.

## Consequences and alternatives
Workspace serialization is a deliberate initial scale tradeoff. Presence and high-volume logs use separate ephemeral/stream paths. A global bigserial watermark can miss late commits when used naively, so it is not the catch-up design. ACL changes require cache purge/resnapshot behavior and cursor expiry is explicit.

## Validation and revisit trigger
Gate: late-commit adversarial ordering, reconnect, retries, partial apply, filtered event gaps, revocation, deletion, and snapshot boundary tests. Profile hot-workspace write contention before replacing the ordering strategy. Never add Kafka merely to avoid specifying these semantics.
